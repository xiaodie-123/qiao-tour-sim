# 项目范围

作品是乔家大院游客行为仿真与拥堵干预沙盘，使用者设定为景区管理人员。首版只展示设定条件下的模拟结果，不声称具备真实景区预测精度。

## 做了什么

- 34 个官方点位（景点 17、院 5、堂院 2、服务点 10），默认 100 名游客，亲子、老年、普通散客三类画像
- 120 个模拟分钟，每步 1 分钟
- 正常游览；第 30 分钟下雨；同样雨情下第 20 分钟开始分流
- 参数、模拟、轨迹回放、拥堵标记、分流对比、结果下载
- 网页用 Streamlit，图用 Plotly，路网用 NetworkX
- 运行时不调用大模型。策略文件可以来自大模型，也可以是标明来源的备用规则

## 明确不做

自由画地图、接入真实客流、消费和票价预测、训练模型、手机 App、多个景区、踩踏风险预测。

右侧建议只解释这次跑出来的排队和走线。页面不写「优化后满意度提升到 90 分」这类没有计算过的话。

## 演示参数

画像比例 30% / 30% / 40%，入园窗 20 分钟，每人最多 4 个目标或 90 分钟个人预算。这些数字可以改，但不是乔家大院真实客流构成。

### 节点表（2026-10-03 更新）

节点名称、点位与来源改用官方资料：`节点.xlsx`（工作表 qjdy_nodes）逐条记录 node_id、官方地图点位编号、名称、类型、经纬度、来源网址与说明，另有 `data/source/qjdy_edges.csv` 记录节点间的「包含 / 位于 / 连接 / 同指 / 又称 / 讲解顺序 / 邻近轨迹段 / 路线下一段」关系及证据等级，`data/source/qjdy_official_route.csv` 记录官方电子导览「全景游」轨迹的 25 个折点。

进仿真路网的是其中 34 个有经纬度、可做停留的点（景点 17、院 5、堂院 2、服务点 10）。没有坐标的结构性条目（乔家大院景区、保元堂、宁守堂、乔家花园、甬道、第一院）和 25 个轨迹折点只作资料保留，不进路网。

节点位置由官方经纬度换算成 0—100 示意图坐标，两轴各自线性铺满，不冒充经纬度。容量、接纳速率、停留时间和遮蔽仍然没有实测来源，按类别写入演示假设值，并在每条记录的 assumption_note 里写明「非实测」。道路把 34 个点按沿线里程排序后相邻相连，步行时间按 1.1 米/秒估算，也是演示假设。

节点 id 从 N01—N42 换成官方点位编号后，`demo/`、`outputs/` 和 `docs/experiment_report.md` 里用旧节点算出的数字全部作废，需要重跑。详见 `docs/node_table.md`。
