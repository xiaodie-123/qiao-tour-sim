## 问题

景区要在改路线、加引导之前知道人会堵在哪。我们做的是乔家大院的演示沙盘：给定地图、人数和天气，回放游客怎么走、在哪排队，并对比开不开分流。它不是实时客流，也不是实测预测。

## 架构

游客分成亲子、老年、普通散客。每一类在晴天和雨天各有一组偏好，一共六组。仿真时每个人还有自己的到达时间、走路、排队和停留。程序不给每个人的每一步都调用大模型。

网页负责设参数、回放和下载。计算在 Python 里完成，点播放不会重算。

## 大模型做什么

大模型只负责生成那六组偏好，并且必须使用给定的节点编号。生成结果已经保存，来源是大模型，模型名是 deepseek-flash。仿真、回放和对比只读这份文件，断网也能跑。若某一组生成失败，页面会标明备用规则，不会把它说成模型生成。

## 演示

先看默认的雨天分流回放：节点变黄、变红表示负荷到了 0.8 和 1。再点“对比雨天与分流”，两条曲线用的是同一个随机种子。右侧同时给出拥堵分钟、平均等待和峰值排队。

## 对比

五个种子里，分流后的拥堵节点分钟平均少 22.8，范围是少 7 到少 42，没有挑最好的一组。平均等待多数变短，但种子 0 的等待从 3.22 分钟增到 3.78 分钟，峰值排队从 7 人增到 15 人。原因是引导会把人送去当时最空的点，总的拥堵分钟下降，但可能挤出一条新的长队。

## 局限

地图坐标、容量、停留和路时都是演示假设。没有真实客流，不能说已经能预测乔家大院。模型没有模拟票价、消费和踩踏。队列中途不能退出，路上的人要走完当前这一段才改方向。
