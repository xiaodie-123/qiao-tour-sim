# 仿真规则

这些规则写在 `simulator.py` 里，用来接受检查，不在出结果之后偷偷改。

## 人怎么选地方

同一类游客共用一组偏好。每个人有自己的位置、已去过的点、等待、停留和固定随机扰动。运行时不为每个人的每一步请求大模型。

负荷 =（节点内人数 + 排队人数）/ 容量。

得分 = 吸引力 − 拥挤厌恶 × min(负荷, 2) − 0.1 × 预计走路分钟 + 下雨时的遮雨偏好 × 是否遮蔽 − 0.5 × 已访问 + 个体扰动。

个体扰动固定在 −0.15 到 0.15，由种子和游客编号决定。遮雨项只在已经下雨的分钟加上，晴天不加。这是对任务书公式里「雨天遮雨偏好」的直接实现。

分流开启后，服从的游客在还没完成、并且走得到的景点和服务点里，改去当前负荷最低的一个。其余人仍用上面的得分。是否服从由种子和游客编号固定，再和页面上的服从比例比较。

去出口的人锁定出口路线，不再被分流叫回去。触发条件：已经完成 4 次停留，或从入园起已经满 90 分钟。人数、目标数和预算以场景配置为准。

## 一分钟里的顺序

1. 原先就在排队的人，这一分钟计入等待。
2. 停留结束的人离开节点，释放容量。
3. 走完当前路段的人到达路段终点。没下雨、没到新的分流状态、也没到该去出口时，按原路线进入下一段，不瞬移。天气或分流状态变了，就在这个节点重新选择。到达原定景点就去排队。到达出口就离园。
4. 按先来先服务放入节点。节点内人数不能超过容量，每分钟放入人数不能超过接纳速率。队列不占节点内部容量，但计入负荷。
5. 刚入园和刚结束停留的人再做新决定。

入口和出口不作为展览停留。排队途中不能退出。

停留分钟 = 节点基础停留 × 画像停留倍数 × 个人系数，四舍五入后至少 1 分钟。个人系数在 0.9 到 1.1。

## 指标

- 某一分钟负荷大于 1，该节点计 1 个拥堵分钟。等于 1 只在图上标红，不算拥堵分钟。
- 拥堵节点分钟是各节点相加，不叫「全园持续拥堵时长」。
- 平均等待 = 已入园游客的累计等待之和 / 已入园人数。没走完的人也算在内。
- 另报峰值排队、已离园、观察结束仍在园。
- 改善率 = (基线 − 干预) / 基线 × 100%。基线为 0 时写「不适用」。负数照写，表示分流后更高。

## 和 RAPPIE 的差别

RAPPIE（Liao 等，ACL 2025）用读者代理做个性化隐式情感分析。这里只借用「一类人共用一套角色化偏好」这一个想法。没有使用该论文的数据、传播图或情感任务，也没有把本项目的得分公式说成论文公式。
